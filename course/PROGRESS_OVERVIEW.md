# 多作品进度总览：读历史记录，不代替实际考试

## 为什么需要进度总览

`learn next <单个工程>` 只能告诉你当前工程下一步。做过三个练习后，可能不记得哪些检查成功、哪些源码改过后旧记录已经过期。`learn overview` **只读**当前目录下的学员工程及 `Studio/` 子目录，自动汇总这些线索。

在完整源码根目录运行：

```powershell
cargo run --offline -p labquest -- learn overview "D:\My-Rust-Learning"
```

Windows 双击 `LEARN_NEXT_WINDOWS.cmd` 输入某个学员工程目录后，可按 **P** 查看与该工程同级的进度总览。若用的是学员包，直接向命令提供学员包的根目录即可。**没有必要把已有学习工程迁移到新版本目录。**

## 四种最常见状态

- **未检查**：项目已存在，但没有符合格式的历史评测报告。请从第 1 步检查。
- **阶段失败 / 编译失败**：报告显示尝试过的范围，必须先处理最前面的错误；不是安装失败的充分证据。
- **源码有改动，旧报告过期**：修改过任何 `src/*.rs` 后，旧报告不能证明新代码。即使旧报告 3/3 也必须重新检查。
- **3/3 历史通过记录**：表示磁盘上存在与当前源码对应的三阶段报告；**不代表实际提交了个人作品，也不代表课程掌握度、平台防作弊认证或教师评分**。

一个总览里的结果仅用于导航；生成报告的文件可以由本机用户编辑，存在被伪造的可能。程序不会扫描整个磁盘，不遍历任意深层目录，不跟随符号链接；支持常见的父目录/Studio 两层布局，异常路径会提供说明。

## 最简单的复盘问题

1. 当前只完成了哪一步？第二步功能依赖第一步的什么能力？
2. 为什么同样的函数换一个输入会得到另一结果？
3. 这款软件的输出是打印文字、写文件还是创建网页？退出后是否还在？
4. 一个错误输入会不会破坏原有数据？如何证明？
5. 使用过提示吗？可以不看提示解释关键函数吗？

建议每完成三个里程碑，再用自己的数据交付一个真实产物，并在 `LEARNING_LOG.md` 写下命令、预期、实际、错误和帮助。不要用总览中的记录条数衡量教学效果。
