# Rust AppLab 网页学习工作台

在同一网页阅读中文任务卡、修改学员工程、运行程序和进行正式检查。适用于 0.19.0-rc.6 源码包和对应平台的运行包。

## 启动工作台

1. 完整解压到可以写入的目录。Windows x64 双击 `START_WORKBENCH_WINDOWS.cmd`。Linux x86_64 在解压目录打开终端，执行 `./START_WORKBENCH.sh`。
2. 启动后保留终端窗口。若浏览器未自动打开，从窗口里的 `RUSTAPPLAB_WORKBENCH_URL=` 后复制完整的 `http://127.0.0.1:端口/` 地址，粘贴到浏览器地址栏。每次启动以当前窗口打印的地址为准。工作台只在本机访问。
3. 学完先保存。回到启动窗口按 Ctrl+C，停止本次工作台服务。

源码包首次打开时，脚本调用 Cargo 编译工作台。运行包自带编译好的 LabQuest，可直接打开页面。两个包都需要本机 Rust/Cargo 和系统构建工具，才能编译、运行或正式检查你的 Rust 源码。Windows 使用 MSVC 工具链及 Windows SDK，Linux 使用本机编译和链接工具。StoreDesk 还需要该课程原有的系统 SQLite 环境。具体要求见 [支持平台](../SUPPORTED_PLATFORMS.md) 和 [StoreDesk SQLite 环境说明](SQLITE_SETUP.md)。

脚本默认用脚本所在目录作为工作区。直接启动脚本且不传参数时，它会尝试打开浏览器。给脚本传入参数时，只有显式传入 `--open` 才会尝试打开浏览器。

## 从 FirstCard 开始

左侧「当前学习」显示正在查看的课程，「后续课程」列出同一阶段接下来的至多两门课。需要查看其他课程时，展开「基础课程」「Rust 专项练习」或「进阶课程」；课程均可自由选择，导航不表示已经完成或掌握。

FirstCard、UnitLab、QuizDeck 的开始页显示成品输出示例，供动手前了解用途；示例不是你的实际运行结果。UnitLab 与 QuizDeck 都要完成全部三步才具备完整软件行为。当前代码检查通过时，「练习与复盘」显示本步练习的知识，继续用自己的输入验证；代码发生变化后，旧的通过提示与复盘总结撤回，需重新检查。其他课程使用任务卡已有的知识点，不假设已制作成品演示。

1. 在「学习路线」选择 **FirstCard · 第一张任务卡**。点击代码区中醒目的「开始本课」，工作台会自动准备 `my-first-card` 并打开代码。如果已经显示你的代码，可以直接继续。
2. 先读「任务卡」里的目标、要改哪里和练习知识。写代码前预测换一组姓名和任务时，输出会怎样变化。卡住时展开「遇到困难？查看提示」，再按顺序查看提示 1–3，需要上下文时点「完整讲义」。
3. 在「源码编辑器」的「文件」中选择 `src/main.rs`。按任务卡修改 `println!` 那一行。点「保存」或按 Ctrl+S，看到「已保存」后，修改就写入当前工程。展开「切换已有项目」可核对当前工程的实际路径。
4. 点击「检查本步」。初始 FirstCard 尚未实现任务要求，检查通常失败。输出保留真实结果，并展开提示入口。若有编译错误，先从第一条报错修起。每次检查前会保存当前编辑器中的修改。检查通过时自动展开练习与复盘，再用自己的输入做实验；经典 Studio 的同源码有效检查记录可恢复下一步入口。FirstCard 不依赖 FIRST_WIN.md：刷新页面时仅向仍在运行的本地服务核验真实检查任务；任务已失效、服务重启或源码变化时重新检查。
5. 展开「修改运行输入」，每行写一个参数。一行内的空格会原样传给程序，无需引号，参数框留空会使用无参数运行。点击「运行程序」，比较实际输出。这里的一次运行成功只代表本次程序执行结束，课程代码检查通过由「检查本步」给出，不等于已经掌握知识。

给 FirstCard 输入下面两行，第一行是姓名，第二行是任务。

```text
林 果
整理读书笔记
```

换一组姓名和任务再运行，然后按「想一想」解释这两次输出为何不同。准备好后，从「下一课 · UnitLab」进入单位换算练习。Studio 的正式检查会一并检查所选步骤和它之前的步骤。

## 打开旧工程与处理冲突

在「学习路线」选对应课程，展开「打开已有项目」（学习中为「切换已有项目」），粘贴学员工程的实际目录，再点「打开项目」。可直接输入含中文或空格的路径，例如 `D:\练习 Rust\我的 UnitLab`。打开会沿用目录中的源码。即使旧工程没有后来才加入的讲义文件，工作台仍会从课程数据提供任务卡和讲义。

如果另一个编辑器已经修改了同一个文件，保存时会提示冲突，草稿会留在网页编辑器里。需要两边的修改时，先复制草稿，再点「重读磁盘版本」并确认，接着把需要的内容合并回来。取消确认可以继续查看原草稿。切换到其他课程、替换当前文件或刷新前，留意未保存修改的提示。

同一个工作台服务中的标签页共享每门课当前选中的工程。如果另一标签页打开了同一课程的另一个工程，先展开「切换已有项目」，核对当前项目的实际路径。换步骤时发现工程已切换且当前页有草稿，会要求你确认是否放弃草稿。选择取消会留在原工程和原步骤。要回原工程续写，可以先复制草稿，再用「打开项目」重新打开原路径并合并修改。

## 按需理解 Rust Book 知识

任务卡中默认折叠的“补充知识（选读）”可打开旧版中文译本与当前官方 Rust Book 的相应章节，并显示对应思考问题。点击外部链接需要网络，但课程原有的任务卡和运行无需联网。不同 Rust Edition 的示例与当前工程的 Cargo.lock 和 rust-version 可能有差别。

点击左侧「查知识 · 找实验」，输入“借用”“HashMap”“单态化”或 `E0502`。选择相关主题后，阅读本地中文讲义、打开当前官方章节，或点击「在工作台学习并验证」进入对应专题。讲义按标题、表格和代码段呈现；当前作品的未保存草稿仍会受到切换确认保护。

D1–D6 使用已有专题源码创建 `my-book-d1` 等个人副本。点击「开始本课」后，在同一个编辑器选嵌套源码文件，先做预测、修改一处，再点「验证专题」。它实际执行所选工作区的所有目标测试与文档测试，D1 同时启用全部 feature。编译失败、断言失败和退出码均在输出区显示；修改源码后重做验证。清单、测试和 Cargo 配置不通过网页编辑，参考工程目录也不会被作为个人副本改写。

D5 的服务器行为用真实测试验证，D6-A 是库与工具练习，因此这两项只显示「验证专题」，不启动长驻服务。D6 的工具链安装、Edition 迁移、nightly、IDE 跳转和 Cargo 发布操作继续按讲义单独执行；网页测试不能代替这些操作。

[31 项概念补课任务](BOOK_31_GAPS_REPAIR.md)包含本次六章抽样内的逐项解释、预测、成功／失败对照、修复与新任务。[学习效果观察协议](LEARNER_EVIDENCE_PROTOCOL.md)用于保留真实理解与迁移证据。

检查失败时，任务卡优先显示简短的原因与下一步建议：已识别的编译错误、功能检查未满足要求、无法执行或尚未识别的失败。只有当前检查的真实诊断才会被解释；能唯一匹配个人可编辑文件时才展示文件与行列，不能确认的错误保留原文。实际编译失败如 E0382、E0502 等，输出区仍提供本地概念解释、官方章节和「运行失败／修复实验」。11 类错误各有两个最小程序：失败版本必须产生指定错误码，修复版本必须编译并运行断言。两者在独立临时目录调用真实编译器，不会覆盖当前项目，也不会记作课程通过；未识别错误仍保留原始诊断。建议按“预测 → 查规则 → 修改自己的代码 → 重新运行检查 → 自己解释”完成练习。网页工作台不自动评分学员概念掌握程度。

## 现代 Rust：先学会使用新版，再扩展到专用工具

此功能属于当前开发候选，不改变历史 rc.5 下载包。先安装 Rust 1.100.0（首次需网络）：`rustup toolchain install 1.100.0 --profile minimal --component rustfmt --component clippy`。E4 还需 `rustup target add wasm32-unknown-unknown --toolchain 1.100.0`。经典 1.74 与 C1/C2 1.85.0 不变。左侧「进阶课程」提供八门无额外 crate 的个人 TODO 工程，按步骤检查真实 Cargo 合同；最后一项执行全部目标与文档测试。每个项目只编辑 src/lib.rs 和学习记录（E2 另可编辑 src/gui.rs），其他固定源、工具链、测试、C/Web 材料不得由工作台覆盖。默认运行入口为有限 Rust example；E4 只在网页做 host 测试，实际 C/WASM 按讲义继续。另外五门依赖课程使用原专项通过验收的离线学员包，按随包 SHA-256 校验并解压到个人目录。选择对应课程，填写含 Cargo.toml、Cargo.lock、vendor 和 .cargo/config.toml 的实际目录，点击「打开项目」。不得选仓库原始模板、不得手改 vendor 或 Cargo 配置；首次冷编译最多 20 分钟，原课程时限不变。工作台不隐式联网下载依赖，vendor 为可信依赖环境，不是工作台编辑或实时逐字节监控范围。修改依赖环境后重新检查。

| 课程 | 离线学员包 | 网页验收 |
|---|---|---|
| D10-B | D10-B-learner-offline.zip | Tokio/Stream 合同及有限示例 |
| E1-A | E1-A-learner-offline.zip | HTTPS/授权合同与有限演示 |
| E1-B | E1-B-learner-offline.zip | SQLite/观测合同与有限演示 |
| E2 | E2-learner-offline.zip | 两个 TODO 文件及真实控件合同 |

离线包现阶段从专项 CI 产物获取，旧 rc.5 不更新。GUI 原生窗口、ARM/QEMU、Miri/Fuzz、Cargo/IDE 和 C/WASM 仍按独立讲义操作；不把 host 测试称为专用工具验收。

## 记录自己是否理解

任务卡展开「练习与复盘」，点击「写学习记录」，打开个人工程中的 `LEARNING_LOG.md`。FirstCard、Studio 和新建 Book 副本都自带空白模板。先写动手前预测，之后补实际输入、退出码、提示使用情况、错误原因和一次新任务；未观察的理解与迁移项目保持“未评估”。日志修改不改变代码验证结果，源码修改会使旧结果失效。旧工程没有此文件时，按钮打开观察协议，按模板自行保存后重开工程。

## 查看输出与恢复连接

一次只运行一个正式检查或个人运行。等待时输出栏会显示状态，操作完成后再显示实际标准输出、错误信息和退出结果。点击「折叠」可以缩起输出，结果摘要仍然可见，任务继续运行。需要更多空间时点「放大」。

等待过程中如果连接中断，先确认启动窗口仍在运行，再点击「继续查询结果」。这个按钮会查询原来那次操作。点「停止等待」只会结束页面的等待。若已关闭服务窗口并重新启动，请使用新窗口给出的地址并按需重新打开工程。遇到课程或文件读取失败时，可用页面上的重试按钮重新加载。

## 指定自己的工作区

把 `EXISTING_DIR` 换成一个已存在、可写入的目录。带空格的路径保留引号。`--port 0` 让系统分配空闲端口。

在源码包根目录运行以下命令。

```sh
cargo run --locked --offline -p labquest -- workbench --workspace "EXISTING_DIR" --port 0 --open
```

Linux 运行包在解压目录执行以下命令。

```sh
./bin/labquest workbench --workspace "EXISTING_DIR" --port 0 --open
```

Windows 运行包在解压目录的终端执行以下命令。

```powershell
.\bin\labquest.exe workbench --workspace "EXISTING_DIR" --port 0 --open
```

## 可以在工作台学哪些课

当前开发候选共 33 个网页学习入口：原有 13 门作品课程、D1–D6 的 7 个专题工程，以及十三门现代 host 课程。原有课程仍是 37 个步骤，FirstCard 有 1 步，以下 12 款 Studio 各有 3 步。

UnitLab、QuizDeck、TextScope、LedgerLite、BadgeForge、TermGarden、BatchMeter、MiniKV、NetFetch、ServiceDesk、StoreDesk、AsyncBoard。

Book 专题为 D1 Cargo、D2 智能指针、D3 对象与模式、D4 高级 Rust、D5 多线程 Web Server、D6-A 附录、D6-B 基础概念。进阶 A/B/C、TaskPocket 和 PageMint 独立作品继续从各自的文档和终端入口学习。需要交互式标准输入或长时间运行的服务时，按该课程原有的终端命令操作。工作台的「修改运行输入」在启动程序时一次性传入。相关入口见 [课程地图](CURRICULUM.md)、[独立作品路线](INDEPENDENT_PATH.md) 和 [Rust Book 对照学习](BOOK_GUIDE.md)。
