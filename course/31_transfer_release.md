# 第 31 关 · 真实作品交付与跨领域复盘

**中心任务**：让 PageMint 脱离样例，整理你自己的真实资料，交付能由另一个人直接使用的离线网页，并解释哪些 Rust 能力能够从 TaskPocket 迁移。

## 一次完整的真实使用

在 PageMint 独立工程里创建 `notes/`，新增三篇属于你自己的笔记（不能全部复制课程样例）。每个 `.note` 的第一行是标题，后面每个非空行是一段正文。然后：

```sh
cargo run -- stats notes
cargo run -- build notes my-notes.html
cargo build --release --offline
```

用浏览器打开 `my-notes.html`，检查文字、中文、符号、标题顺序和长段落换行；另找一个你平时会查看笔记的设备或不同浏览器试用（若不可用，如实记录未验证）。把 `src/`、`Cargo.toml`、示例输入、独立 HTML 和使用说明作为一份独立作品交付。

**注意**：`build` 拒绝覆盖已存在的 HTML。要更新时请自行核对旧版文件，再换一个新输出名；这不是一个无提示覆盖的同步工具。

## 自己构造失败场景

先保存旧输出，然后分别建立测试目录：一份 `.note` 第一行为空白；一份含 HTML 特殊符号；一份不是有效 UTF-8；一份带子目录或其他扩展名。观察程序是否按照合同拒绝损坏输入、保留旧文件、忽略不需要处理的内容。

在 RustAppLab 根目录进行行为回归：

```sh
cargo run -p labquest -- app check pagemint my-pagemint
```

Linux/macOS/Windows 的符号链接权限不同，Linux/Unix 有第九组符号链接测试；其他平台只运行可移植的八组。**8/8 和 9/9 不应当混为同一组测试证据**。评测器不是安全沙箱，不要对从陌生来源下载的代码使用。

## 从“会模仿”到“会设计”的迁移对照

| 问题 | TaskPocket | PageMint | 需要解释的 Rust 概念 |
|---|---|---|---|
| 程序输入 | 命令 + TSV 数据文件 | 命令 + 笔记目录 | `args_os`、`PathBuf` |
| 数据结构 | ID、状态、标题 | 文件名、标题、多个段落 | `struct`、`Vec`、所有权 |
| 数据流向 | 内存修改 → 落盘持久化 | 多文件 → 排序 → HTML | iterator、`Result`、模块划分 |
| 风险边界 | 错误输入不得改写旧数据库 | 危险文本不得变成可执行标签 | 输入验证、正确输出编码 |
| 作品形式 | 可持续增删的 CLI 工具 | 离线可查看的网页 | Release、用户文档、跨设备测试 |

请在 `PROJECT_JOURNAL.md` 回答：如果现在要求你独立写一款“把日志统计转换为静态网页”的小工具，你是否能从零列出数据结构、API 和三个失败场景？先写计划再看已有 LogLens 的源码。这个练习是迁移效果的主观记录，不计自动分数。

## 教学闭环的验收标准

- 工程源码能脱离 RustAppLab Workspace 独立编译运行；
- PageMint 通过当前平台可执行的全部基础行为检查；
- 至少三份**自己创作的真实笔记**成功生成离线 HTML；
- 交付 `PROJECT_JOURNAL.md`，记录至少两次失败和修复；
- 能解释 HTML 转义为何与 TaskPocket 的 TSV 校验是不同问题；
- 明确报告跨平台 / 浏览器 / 真实用户尚未测试的部分。

完成后，可以选择改善网页版式或增加离线全文搜索，但必须先描述真实用户的使用障碍，再选择技术，而不是为了使用框架而增加框架。
