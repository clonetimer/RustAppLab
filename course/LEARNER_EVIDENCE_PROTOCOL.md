# RustAppLab 学员真实学习效果观察协议

本文件提供可执行的人工观察步骤和空白记录，**没有报告已经完成的真人试验或学习收益**。CI 全绿不能说明学员掌握 Rust；作品自动检查通过只说明本次代码满足已测试合同。理解、迁移和自主完成在实际观察前均为“未评估”。

## 1. 从哪里记录

新建 FirstCard 和 Studio 工程时就有 `LEARNING_LOG.md`，可以先写预测，再改源码。在工作台选择该文件并保存；检查不会代填它。旧工程没有这个文件时，把 [空白学习记录](LEARNING_LOG_TEMPLATE.md) 另存为自己工程中的 `LEARNING_LOG.md`，再重新打开工程。不要覆盖原有笔记。独立作品也可沿用自己的 `PROJECT_JOURNAL.md`，按本协议补充每次观察。

个人自学可以只填写学习记录；正式教学试用另由观察人填写 [实际试用记录](USER_TRIAL.md)。D1–D6 是参考实验，先在自己的副本修改，保留原始参考代码。讲义、参考测试和维护者的自动演练均不能署名为学员的独立作品。

## 2. 每个任务怎样观察

1. **准备。** 在学员自愿并知情的前提下约定匿名代号、记录用途和保存位置。记录软件版本、提交或包 SHA-256、任务 ID、环境、起止时间和观察人。记录学员已有经验、先前是否看过这道题或参考答案。保留起始源码，核对操作的是个人副本。
2. **A 轮：基线独立尝试。** 先读题，写预测和时间，再修改、运行。保存输入、源码变更、完整命令、stdout/stderr 和退出码。观察人记录卡住的位置，不把答案写进学员源码。环境未就绪应记为环境阻断，不把未开始的题目计为能力 0 分。
3. **B 轮：必要提示后重试。** 如果需要帮助，逐层提示；记录级别、内容、时间和其他来源（讲义、参考代码、他人、AI）。保留 A 轮原记录，不用 B 轮答案覆盖它。B 轮说明“在这些帮助下完成”，不记为独立完成。
4. **C 轮：换题独立迁移。** 给出没有做过的新输入、边界或设计变更，先预测再尝试；记录与原题的差异。不得直接重放刚看过的参考答案。若又需要提示，如实记录并结束“独立”标签。可以另约延后复测，但必须记录实际间隔，不能从当场通过推断长期掌握。
5. **人工复核。** 请学员用自己的话解释一条 Rust 规则、一次失败的原因和一个反例。观察人保留原话或准确摘录，并对照实际源码、日志和新测试记录判断及限制。没有发生的操作、尚未观察的维度一律留空或写“未评估”。

不要一次要求初学者做完下面所有路线。先根据已学内容选任务；同一轮选相近难度，记录任务版本。FirstCard、UnitLab、独立作品是现有发布规则要求的观察路线；TextScope 与 D1–D6 用于对应教学内容的专项评估，不因其中一项通过而宣称整个主题已经掌握。

## 3. 可直接安排的观察与迁移任务

表中的 A/C 是两道任务的建议，均无预填成绩。需要错误解释时，可用课程内已有 TODO 失败或可恢复的编译错误，不制造未定义行为。具体运行入口以各课讲义和个人副本 README 为准。

| 任务 ID／入口 | A 轮：观察与预测 | C 轮：换题迁移 | 必须保留或追问的证据 |
|---|---|---|---|
| `firstcard-01` · [FirstCard 后续](AFTER_FIRSTCARD.md) | 预测两组姓名与任务会改变哪些输出；自己修改 `println!`，记录初始检查失败和修改后的结果。 | 不改源码，使用自己设计的含空格／中文参数，再尝试只传姓名或不传参数；预测哪些默认值会出现。 | 两轮输入和输出；解释变量插值与写死文本的区别。只验证这一行的迁移，不称为已经独立实现参数解析。 |
| `unitlab-01` · [UnitLab](studio/unitlab.md) | 先预测一个非示例温度的返回值；完成函数，解释返回表达式与打印文本的区别。 | 三步完成后自行选反向换算、跨类别单位、无法解析的输入，各增加一个测试或实际 CLI 记录。 | 合法值、错误输入的输出和退出码；解释 `Result` 为什么不能用数值 0 替代，以及 `?` 在哪里结束失败路径。 |
| `textscope-01` · [TextScope](studio/textscope.md) | 对自己的中英文文本先预测 bytes、chars、lines、words，再运行核对。 | 换成含 CRLF、空行、组合字符的新文本，设计空查询和无匹配查询；新增至少一个边界测试。 | 预测差异、输入文件、测试和输出；解释 `&str` 结果借自哪个值，以及字符数为何不等于字节数或显示字形数。 |
| `independent-01` · [独立作品](INDEPENDENT_PATH.md) | 在 TaskPocket 或 PageMint 用自己的需求拆分、测试与输入完成一项功能，记录用了哪些既有样例。 | 观察人给一个未见过的边界：如损坏数据、含特殊字符的文本或已有输出路径。由学员先说明合同再设计自己的测试。 | 个人源码、预期和实际产物、失败路径及解释；不能只提交平台参考输出。 |
| `d1-01` · [D1 Cargo](BOOK_D1_CARGO.md) | 在副本指出 Workspace、库、CLI 与共享锁；预测直接运行二进制和 `cargo applab-map` 的参数差异。 | 为自己的 `book-card` 新增一个主题，增加合法、未知主题和多余参数的测试，重跑库与 CLI。 | 依赖关系、修改、真实命令和退出码；解释为何根 Workspace 配置 profile，且本地安装不等于 registry 发布。 |
| `d2-01` · [D2 智能指针](BOOK_D2_SMART_POINTERS.md) | 先画 `Rc`／`Weak` 父子关系，预测释放最后一个强引用前后 `upgrade()` 的结果。 | 为新的父子节点组合增加“父节点先释放、子节点保留”的测试；再设计一次 `RefCell` 借用冲突并用可恢复接口处理。 | 强引用计数或 Drop 观察、错误结果及新测试；解释非拥有回边为何不维持父节点存活。不运行故意泄漏的强引用环。 |
| `d3-01` · [D3 对象与模式](BOOK_D3_OOP_PATTERNS.md) | 预测 `AveragedCollection` 清空后再添加数据的平均值，指出必须一起维护的字段。 | 在副本实现 `clear` 并测试空集合和再次添加；另选一个未见过的模式输入说明命中分支。 | 变更前后测试、私有字段不变量的解释；若评估 trait object，另安排新 `Draw` 类型，不把平均值任务当作动态分发证明。 |
| `d4-01` · [D4 高级特性](BOOK_D4_ADVANCED_FEATURES.md) | 预测返回闭包在两个捕获值下的输出，指出保存的值来自哪里。 | 把同一闭包规则用于一个新的捕获值和边界输入，新增测试；解释能否改成普通函数指针及原因。 | 捕获与调用的解释、个人测试和实际结果。unsafe、trait 和宏另行选题；任何 unsafe 修改只使用满足安全契约的输入。 |
| `d5-01` · [D5 Web Server](BOOK_D5_WEB_SERVER.md) | 画出任务入队、执行、关闭消息、join 的顺序；预测作用域结束时完成计数。 | 自行增加不同任务数和 worker 数的测试，验证任务排空与最大并发；说明为什么单次响应先后或耗时不能证明并发正确。 | 真实测试、计数和关闭解释；浏览器能打开首页不能代替这项证据。 |
| `d6a-01` · [D6 附录](BOOK_D6_APPENDICES.md) | 给包含 `String` 的结构体选择派生 trait，先解释哪些实现受字段类型约束。 | 换一个字段组合，分别预测 `Debug`、`Clone`、`Copy` 的可用性；保存一次预期编译失败及修复，解释 `Display` 的用途。 | 自己的结构体、编译诊断、修复和解释；不能仅抄派生 trait 清单。 |
| `d6b-01` · [D6 基础](BOOK_D6_FOUNDATIONS.md) | 预测数组边界访问、可恢复输入错误的结果，指出应由 `Option` 或 `Result` 表达的失败。 | 以新的记录格式写一个小解析或汇总测试，覆盖空数据、有效数据和损坏行；解释选择的错误边界。 | 输入、个人修改与新增测试；说明 `panic` 与正常输入错误的区别。 |
| `d6-tools-01` · [D6 工具实操](BOOK_D6_PRACTICAL.md) | 在保留副本完成工具检查；亲自在 IDE 跳转、制造并修复类型错误，记录实际扩展/server 版本。 | 换一个符号和诊断复测；选修 Edition 迁移时在副本修改测试输入，解释先 fix 后改 edition 及 Edition/MSRV 的区别。 | IDE 实际操作、时间、版本、命令与 diff；CLI PASS 不能填成 IDE 已通过，Nightly 也不能填成默认 Stable 验证。 |

## 4. 人工评价准则

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 行为预测 | 已观察到无法预测或明显错误且无法解释 | 借助提示后合理 | 独立预测并说明前提 |
| 错误解释 | 已观察到无法定位或编造原因 | 提示后找到规则 | 独立用 Rust 规则定位并修复 |
| 输入迁移 | 已观察到只会重放默认示例 | 能改一组输入，但仍需帮助解释 | 能独立设计新输入与反例，解释边界 |
| 自主完成 | 已观察到只照抄参考实现 | 分级提示后完成 | 独立完成并能复现操作 |

评分由观察人在看过真实证据后填写，不由网页、CI 或导出工具推断。未观察填“未评估”，不得以 0 代替缺失值。只有四个维度全部观察后才可记录 0–8 总分；总分是教学描述，不是发布门槛或 Rust 能力认证。保留 A/B/C 分轮记录，不把提示后的分数记为基线。

## 6. 本机保存与分享

保存个人源码、原始输入、命令日志、迁移作品和观察笔记。每次观察用新会话目录，文件名用代号；失败记录也保留。分享前去掉姓名、磁盘绝对路径和私人数据，对整理后的副本重新计算 SHA-256；私人原件可仅在本机保管。网页不会自动把这些人工记录上传服务器，也不会自动给出理解分数。

工程检查记录和人工观察分开存放。普通学员不需要准备下面的发布 JSON。维护者只有在真实观察和人工复核完成后，才可整理这些文件用于发布规则核对；不能用 CI、自动修复 TODO、测试夹具或 AI 扮演的学员替代。

## 7. 维护者的人工证据索引

`scripts/release_decision.py --learners` 仅接受有人工复核来源、绑定当前版本和源码、附有可核验文件的索引。它校验字段、路线和文件哈希，**无法自动认证“真人确实参加”或解释是否正确**；复核人须查看原始材料并承担该判断。当前候选发布汇总仍把真人观察标记为 PENDING，不会因补齐本协议自动发布 Stable。

下面是不能通过验收的空白索引；在没有真实材料时保持原样，不填虚构姓名、日期、哈希或 PASS：

```json
{
  "schema": 1,
  "version": "",
  "source_id": "",
  "source_id_after": "",
  "status": "UNASSESSED",
  "method": "",
  "reviewer_id": "",
  "reviewed_at": "",
  "unresolved_blockers": null,
  "observed_tasks": []
}
```

真实复核后的索引约定如下。`version` 与 `source_id` 必须对应要发布的当前源码；`source_id_after` 仍是平台源码身份，学员练习中的代码变化另由证据文件保存。实际完成的人工复核使用 `method: "reviewed-human-observation"`；`status: "PASS"` 是复核人的声明，不由本脚本生成。`unresolved_blockers` 只有经核实确实没有阻断时才能为 `[]`。

- `observed_tasks` 包含 `firstcard`、`unitlab`、`independent` 三条路线，每项为 `{"route": "…", "record": "sessions/….json", "sha256": "…"}`。可以记录多个会话，不能重复会话 ID。TextScope、D1–D6 的专项记录另存，不冒充这三条发布路线。
- 每个会话 JSON 包含 `schema: 1`、`kind: "human-learner-session"`、`version`、`source_id`、`route`、`session_id`、`learner_id`、`observer_id`、`observed_at`、`task_id`、`prediction`、`explanation`、`error_explanation`、`transfer_task`、`transfer_result`、`hints_used` 和 `artifacts`。解释字段保存实际观察材料或准确摘录，不能填模板占位词。`hints_used` 是帮助描述的字符串数组，只有已观察到没有使用帮助时才填 `[]`。
- `observed_at` 和 `reviewed_at` 使用含时区的 ISO 8601 时间；实际轮次、预测先后、使用帮助的时间保存在会话材料中。
- `artifacts` 至少包含三份不同文件，分别标记 `kind: "learner_source"`、`"command_log"`、`"transfer_work"`，每项另有 `path`、`sha256`。源码证据可为包含基线与修改的文本 diff；命令日志保留命令、输入、stdout/stderr 与退出码；迁移作品保留新测试、结果及独立解释的原始记录。
- 所有 `record` 和 `path` 相对于索引所在目录，使用 `/`，不得含 `..`、绝对路径或符号链接。单文件最多 4 MiB；较长材料拆成多份同类文件。SHA-256 使用 64 位小写十六进制。PowerShell 可用 `(Get-FileHash -Algorithm SHA256 文件路径).Hash.ToLowerInvariant()`，Linux 可用 `sha256sum 文件路径` 核对真实文件；正文更改后重新计算。

任何缺失路线、占位记录、未解决阻断、不同源码／版本或被修改的文件均不能满足这项门槛。即使字段与哈希全合格，也只能说明人工提交的材料完整且字节一致，不能由软件推断实验真实性或学习效果。
