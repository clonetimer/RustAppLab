# 验证记录与开发经验

本目录供维护者查阅工程检查、发布证据和开发经验。第一次学习请打开 [开始指南](../README_START_HERE.md)，已有作品请使用 [课程入口](../course/README.md)；不需要按本目录的文件顺序学习，也不需要运行发布验收脚本。

## 先确认记录适用于哪个版本

当前发布要求只有一个入口：[发布规则](../RELEASE_POLICY.md)。支持范围见 [支持平台](../SUPPORTED_PLATFORMS.md)，尚未验证或不承诺的能力见 [已知边界](../KNOWN_ISSUES.md)。

下表是仓库内保存的记录索引，不是一张“当前提交全部通过”的成绩单。每份记录只证明它实际列出的源码、工具链、平台和检查范围；同一个版本号下的不同提交也需要分别核对。当前提交的最终结果以对应 CI 和交付记录为准，历史通过不会自动继承。

## 查找更早的版本

[历史记录索引](archive/README.md) 汇总归档范围。[0.19 之前的记录](archive/pre-0.19/README.md) 保留 0.3–0.18 的资格说明、原始日志、报告和截图；旧文中的“当前”“本轮”均指当时的版本。

工程检查证明软件在所列条件下的行为。学员是否亲手完成、能解释概念、能换输入独立使用，仍应由自己的源码、运行结果与学习记录说明。

## 保存新证据

为新的检查使用新的输出目录，记录版本或提交、环境、实际命令、退出状态和原始日志。不要覆盖历史失败记录，也不要把旧报告改名后作为新提交的验证。构建缓存、临时下载与工作副本用于执行检查，本身不代表任何通过结论。
