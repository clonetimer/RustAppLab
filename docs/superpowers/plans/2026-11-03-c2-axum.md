# C2 Axum ServiceDesk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver a runnable, teachable Axum service with durable ServiceDesk operations, graceful shutdown, concurrency tests and offline learner/reference kits.

**Architecture:** Independent workspace reusing the existing ServiceDesk business crate through a path dependency; a bounded mpsc actor serializes writes off the Tokio event loop, Axum handlers expose JSON. Runtime and learner TODOs stay isolated from the Rust1.74 base workspace.

**Tech Stack:** Rust 1.85, Tokio 1.48.0, Axum 0.8.8, Serde, Reqwest(test), Cargo vendor, GitHub Actions.

**Spec:** ../specs/2026-11-03-c2-axum-design.md

## Global Constraints

- Keep root Rust1.74, B4, C1 and sync ServiceDesk behavior unchanged.
- Network binds strictly 127.0.0.1, no TLS/public use. 2048 byte JSON body max, no CORS.
- Startup requires existing, valid ServiceDesk journal. No silent reset/overwrite or automatic repair.
- Use exact Cargo-generated lock and verifiable vendor ZIPs on Linux and Windows.
- Avoid claiming GitHub Windows Server equals local Windows10 acceptance.

## Review Focus

- Simultaneous creates must not reuse IDs or lose state; test at least 48 parallel TCP requests and restart.
- In-flight request completion during shutdown, new connections refused, no unbounded task spawning.
- Corrupt/truncated journal and read-only destination should surface errors without inventing success.
- Malformed JSON, oversized body, custom-header bypass and cross-origin form attempts must not write.
- Offline ZIP must include unchanged legacy domain source and compile after relocation with empty CARGO_HOME.
