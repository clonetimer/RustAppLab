# 网页学习工作台：实现与维护经验

本次改动连接 FirstCard 与 12 款 Studio 的读课、修改、保存、检查和反馈。设计见 [规格](superpowers/specs/2026-11-23-browser-learning-workbench-design.md)，交付步骤见 [实施计划](superpowers/plans/2026-11-23-browser-learning-workbench.md)。

## 保留一个教学事实来源

课程目录和 37 个步骤复用原有课程卡。完整讲义以沙箱 iframe 展示内置 HTML；正式检查通过字面参数启动当前 `labquest learn check`，普通运行调用 Cargo。两类结果分别标记。原有历史记录仅作为历史，FirstCard 的 `FIRST_WIN.md` 不能独立证明当前代码已经通过。

## 文件版本需要包含工程身份

仅用文件内容计算保存版本不足以应对两个标签页切换同一门课的两个工程，因为初始源码可能相同。文件修订号同时绑定规范化工程路径、相对文件名和内容，源码摘要也绑定工程身份。页面在文件读取、保存和运行时回传预期工程路径，服务端在同一把工作区锁内核对；不以请求前先刷新一次代替原子核对。

发生冲突时保留草稿并返回 409，学员决定怎样合并外部改动。打开已有工程只读识别，缺少新文档时从内置教学材料补充显示，不重新生成或覆盖源码。同课程换步骤也必须比较工程身份，不能只根据课程编号推断草稿仍属于当前工程。

## 操作状态与结果必须可追溯

服务一次执行一个运行或检查，任务有独立编号。页面收到编号后即使查询失败，也继续查询同一任务。任务记录真实退出码、输出和启动时源码摘要；查询结果时再次比较当前源码。源码或所选工程变化后，旧结果显示失效状态。

命令使用原生参数向量，不拼接 shell。运行输出有容量上限，执行有截止时间，标准输入关闭。当前输出在结束后显示，界面用明确状态解释等待；这不是逐字流式终端。

## 本地服务的边界

只监听 `127.0.0.1`。HTTP 请求要求准确的本机 Host；写操作要求同源 Origin、工作台自定义请求头和固定表单编码。请求体、头部、可编辑文件及运行参数分别限制大小。资源内置，文件访问限定为所选工程的允许清单。

工作台用于学员信任的工程，与原有 CLI 一样会执行其代码；不能据此宣称公网部署、账号认证或恶意程序隔离能力。

## 验证分层

原生命令测试验证实际 FirstCard 失败→修改→通过、UnitLab 分步结果、中文路径、已有工程、冲突、重复操作及旧成绩失效。模型测试检查课程来源、项目识别、路径和容量边界；JavaScript 状态测试检查结果分类和请求绑定。

真实浏览器验收通过本地实际服务操作，不替换 API 为模拟成功。截图覆盖 1440×1000、1366×768、390×844 和 320×844，并与未改动的原离线讲义页面比较。原生运行包在独立中文目录解压后验证启动、静态资源、课程内容和旧工程读取，防止开发目录中可用而下载包缺资源。

Rust 1.74、Windows/Linux 和旧课程完整回归由现有 CI 按同一源码提交执行。浏览器报告绑定版本、源码摘要及操作记录；源码变化后不能沿用以前截图作为新版本准入。自动化修改 TODO 是工具验收，不代表真人已经学会课程。
