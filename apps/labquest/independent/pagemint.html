需求合同自己的测试交付清单

PageMint：把自己的笔记变成离线网页

这次不是换个名字再写任务列表

TaskPocket 的核心是修改持久状态；PageMint 的核心是把许多输入转换成一个完整产物。你要交付一个 Rust 程序，用自己的 .note 笔记生成单文件 HTML，离线打开即可阅读，不依赖账号、网络或 CDN。先正确处理内容，再决定是否加 CSS。

这是一项独立实现：你设计 Note 的字段、读取函数、渲染和写入边界，不要求照着特定函数名写。先修建议为 TextScope、BadgeForge 和至少一次文件读写实验。TaskPocket 不是机械复制的模板；只能迁移参数解析、错误传播、测试与交付方法。

CONTRACT.md 定义标准，PROJECT_JOURNAL.md 记录你自己的设计。新生成工程里的业务是未完成的，不要把第一次 FAIL 当作环境安装失败。

分清工作目录

在本学员目录运行自己的软件：cargo run --offline -- stats samples/notes。回到完整平台根目录才运行 cargo run --offline -p labquest -- learn check "本工程完整路径" 1。Windows 续学菜单 L/E/C/S/G 同样适用；没有新版 START.html 的旧工程，可以用平台 INDEPENDENT_PATH.html 与 CLI，已有代码不用覆盖。

动手前：写清输入、输出、不变量

逐个打开 samples/notes 中的两份文件：第一行是标题，之后每个非空行是一段。先手算笔记数和段落数。写下：输入目录是否递归；如何定义有效笔记；输出是否允许在输入目录内；发生输入错误时磁盘上应该留下什么。不要自己改合同来省掉难点。

画出一条流水线：参数 → 收集路径 → 读取与校验 → 排序 → 统计或渲染 → 创建输出。把文件 I/O 留在边界，便于对字符串转换写小测试。这里的 pipeline 是你画出的数据流，不是必须引入任何第三方库。

检查点 1：只读统计

只实现 stats，不用实现 build。直接子级的普通 .note 文件参与统计，.txt、子目录都跳过；标题去除前后空白，正文跳过空行，CRLF 与 LF 都能处理。内存数据可用拥有字符串的 Vec<Note>，避免借用已经被释放的临时读取结果。

# 学员目录；附带两个样例共四段正文
cargo run --offline -- stats samples/notes

预期为 notes=2 paragraphs=4。复制一份样例到自己的新目录，在一份正文中增加一个非空行，计数应该增加一，而不是标题数增加。放一个 .txt 和带 .note 的子目录，结果不应变化。统计不得创建网页，也不能改写原笔记。

平台检查点 1 只要求上述只读行为，并使用不同输入；固定输出“2/4”无法通过。先设计一项自己的读取测试，预测输入，再记录实际结果。

检查点 2：生成完整、可读、安全的 HTML

先实现纯转换，再连接输出。笔记按文件名排序，而不是按文件系统刚好给出的顺序。每份笔记生成一条 article，标题放 h2，段落放 p；所有外部文本都按合同转义，包括 article 属性中的文件名。& < > " ' 五类字符都要考虑。

cargo run --offline -- build samples/notes samples/my-notes-01.html

预期 stdout 是 built=2。现在可以双击网页看到自己的笔记；再用编辑器查看 HTML，确认文本已转换为结构。样例中有 <script>，它应显示为普通文本，不能变成活动标签。正确转义不等于完整网页安全审计，后续新增 URL、JavaScript 或 Markdown 需要另行设计。

用自己的笔记改标题、增加段落，再输出到 my-notes-02.html。保持之前产物，比较真实变化。输出名称不同不是重复劳动，而是在遵守“不覆盖”的合同。先让内容对，再改善排版；不要通过 CSS 把缺失的内容隐藏掉。

检查点 2 会复查空目录、排序、动态输入、UTF-8、转义和过滤规则，仍不宣称异常处理已经完整。

检查点 3：坏输入不能产生伪成品

在独立试验目录准备四种错误：标题只有空白；无效 UTF-8；输出文件已存在；输出位于输入目录内。逐次运行，观察非零退出码、错误信息以及文件系统状态。保留输入出错前的有效网页，确认它没有被覆盖。不要在自己的唯一笔记上制造故障。

为什么要先加载全部笔记再写？如果第一篇就写入目标，第三篇才发现坏输入，可能留下貌似完整的半成品。先验证不能消除所有磁盘 I/O 失败，但能阻止这类输入错误造成的半成品。OpenOptions::create_new(true) 用于拒绝已有路径；不是简单“先 exists 再 File::create”，也不是自动回滚或并发安全的通用保证。

Unix 额外验证 .note 符号链接。Windows 不以缺少建立符号链接的权限判学员失败；因此完整探针数可能因平台不同而不同，验收结果需附平台。

# 平台根目录
cargo run --offline -p labquest -- learn check "D:\RustLearning\my-pagemint" 3
cargo run --offline -p labquest -- app check pagemint "D:\RustLearning\my-pagemint"

第三检查点和原 app check 使用同一组完整合同，不放宽标准。.app-reports 保存每次记录；APP_ASSESSMENT.md 仅由完整验收更新。源码、测试或配置改变后历史进度会提示过期，不会自动变成新版本的合格证。

自己设计测试，不只消费评测结果

默认 cargo test 只检查缺参数的入口烟测，个人回归测试有 ignore 且尚未实现。请按 TEST_PLAN.md 修改 tests/self_check.rs：在临时目录造一份标题含 &、正文含 <script> 的笔记，生成新网页，断言真实文件包含转义文本且不包含活动 script。再写一项重复输出拒绝且旧文件字节不变的测试。

最初写断言时，先让缺陷触发红色，再修业务代码变绿。不要把“运行了但没有 assert”当成测试；也不要为满足输出把错误行为写进断言。最后取消 ignore，并保留 cargo test 输出。平台检查不运行你自己的测试，两份证据必须分开说明。

发布一份可携带的笔记集

选用自己真实使用的三份非敏感笔记，生成网页，在关闭网络的条件下打开阅读（无需更改系统网络策略）。记录标题、段落、排序是否正确，浏览器视觉观察不由命令行自动断言替代。

按 RELEASE_CHECKLIST.md 保留源码、测试、样例、实际 HTML、说明和学习记录。写明“不支持递归、Markdown、图片或自动覆盖”等边界；不要把想做的功能写成已经实现。Windows 程序在默认目标目录是 target\release\pagemint.exe，Linux 无后缀。换一个工作目录，用完整输入/输出路径运行一次，证明没写死开发机路径。

迁移复盘：相比 TaskPocket，哪些类型和错误处理方法可复用？为什么本应用先收齐输入再输出，而另一个应用必须加载旧状态后修改？把答案写入 PROJECT_JOURNAL.md，再自行选一项扩展（搜索、标签或主题）写需求与测试，不要直接复制完整答案。
