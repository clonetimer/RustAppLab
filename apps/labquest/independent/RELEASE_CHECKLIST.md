# 从检查通过到交付一个作品

这是人工交付清单，不是自动资格证。不要把打勾数量当作已掌握 Rust 的证据。

## 1. 核心行为与自己的测试

- [ ] 在平台执行完整 `app check` 或 `learn check <工程> 3`，保留本次报告；报告对应当前源码。
- [ ] 完成 `tests/self_check.rs` 个人作业，取消 ignore，执行 `cargo test --offline`；写明任何仍然忽略的测试。
- [ ] `cargo fmt -- --check`、`cargo clippy --offline -- -D warnings`、`cargo build --offline --release`。缺 rustfmt/Clippy 时安装对应组件，不把缺组件称作业务缺陷。
- [ ] 写一个失败用例并证明文件没有被意外改写。仅有错误退出码不够。

## 2. 在自己的数据上使用

TaskPocket：使用非敏感的个人任务，新增、完成、退出后读取、换第二个数据库。PageMint：使用至少三份非敏感笔记生成实际网页，并人工打开查看文本和排序。使用平台教师 fixture 的结果只能叫维护者演练，不能叫学员独立作品。


## 4. 换目录验证可携带性

关闭正在运行的程序，创建一个新的交付目录。复制源码（Cargo.toml、Cargo.lock、src、tests）、样例、文档和实际产物，不复制 target 缓存。使用新目录里的 Cargo.toml 编译一次，并从另一个工作目录传入完整输入路径。

Windows 和 Linux 二进制不能互换。默认目标目录中 Windows 是 `target\release\<程序名>.exe`，Linux 是 `target/release/<程序名>`；如设置了 CARGO_TARGET_DIR，以实际输出为准。程序通过本机检查不自动继承 Rust AppLab 平台的 RC/Stable 资格。

## 5. 下一款软件由你提出

不要直接再做一份同样的待办列表。写出一个新的用户场景、一种输入、一份有用产物、两项异常和一项验收标准。先证明最小功能有用，再加界面。这个设计任务由教师或同伴讨论，不以自动“已完成”标签代替。
